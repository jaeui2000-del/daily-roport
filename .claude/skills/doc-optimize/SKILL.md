# 문서 최적화

세 문서의 역할을 명확히 분리하고 중복 없이 최소한의 내용만 유지한다.

## 각 문서의 역할

| 파일 | 독자 | 질문 | 변경 빈도 |
|------|------|------|-----------|
| `SOUL.md` | 사람 (why) | 왜 이 프로젝트가 존재하는가 | 거의 없음 |
| `README.md` | 사람 (what/how) | 무엇이고 어떻게 쓰는가 | 구조 변경 시 |
| `CLAUDE.md` | Claude (instructions) | Claude가 어떻게 작업하는가 | 워크플로 변경 시 |

## 절차

### Step 1 — 현재 상태 파악

세 파일을 병렬로 읽는다. 없는 파일은 새로 만들어야 한다.

각 파일에서 다음을 확인한다:
- 다른 문서와 겹치는 내용이 있는가?
- 해당 문서의 독자에게 불필요한 내용이 있는가?
- 누락된 필수 내용이 있는가?

### Step 2 — 분류

모든 내용을 세 버킷으로 분류한다:

**SOUL.md에 속하는 것**
- 프로젝트 존재 이유, 목적
- 설계 원칙 (왜 이렇게 만들었는가)
- 대상 독자 정의

**README.md에 속하는 것**
- 프로젝트 한 줄 설명
- 기능/섹션 목록
- 파일 구조·네이밍 규칙
- 실행 방법, 기술 스택

**CLAUDE.md에 속하는 것**
- 작업 절차 (단계별 지침)
- 파일 수정 시 주의사항 (인코딩, 도구 선택 등)
- 컨벤션 (명명, 포맷)
- 사용할 GitHub 슬러그, 브랜치, 스킬

### Step 3 — 작성 원칙

- **중복 금지**: 한 사실은 한 문서에만 존재한다. 다른 문서에서 참조가 필요하면 파일명만 언급한다.
- **최소화**: 독자가 필요한 것만 담는다. SOUL.md는 Claude가 읽을 필요 없고, CLAUDE.md는 방문자가 읽을 필요 없다.
- **Edit 도구 사용**: 한글이 포함된 파일은 반드시 Edit/Write 도구로 수정한다 (PowerShell Set-Content는 한글 깨짐).

### Step 4 — 커밋

```
git add CLAUDE.md SOUL.md README.md
git commit -m "Optimize docs: clarify role separation and remove duplication"
git push origin <current-branch>
```
